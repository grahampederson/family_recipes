# Family Meal Planner

A Dockerised meal planning tool that uses a locally running [Ollama](https://ollama.com) LLM to generate a week of family dinners, save each recipe as a Markdown file, build a consolidated grocery list, and optionally render everything into a single printable PDF.

---

## How it works

1. **`run.bat`** loops through Monday–Sunday, calling Ollama once per day to generate a recipe tailored to your family's preferences and dietary restrictions.
2. Each recipe is saved as its own Markdown file. After all 7 days are generated, a second pass consolidates the ingredients into a single categorised grocery list.
3. A `recipe_history.json` file accumulates every meal ever generated. On subsequent runs this history is injected into the prompt so the model never repeats a meal.
4. **`make_pdf.bat`** converts the most recent week's Markdown files into a single formatted PDF, ready to print.

---

## Prerequisites

| Requirement | Notes |
|---|---|
| [Docker Desktop](https://www.docker.com/products/docker-desktop/) | Must be running before you use either script |
| [Ollama](https://ollama.com) | Must be running on Windows with `llama3.1` pulled |

### First-time Ollama setup

Ollama defaults to listening on `localhost` only, which means Docker containers can't reach it. You need to open it to all interfaces once:

1. Open **Windows Command Prompt** (not PowerShell) and run:
   ```
   setx OLLAMA_HOST 0.0.0.0
   ```
2. Quit Ollama from the system tray and relaunch it.
3. If you have Windows Firewall enabled, add an **inbound rule** allowing TCP port `11434`.

You only need to do this once — the setting persists across reboots.

## Usage

### Generate a week of recipes

Double-click **`run.bat`**, or from a terminal in this folder:

```bat
run.bat
```

This will:
- Build the Docker image (first run only — takes a minute)
- Connect to Ollama and generate 7 dinners one day at a time
- Save dated Markdown files to `recipes/`
- Append all meals to `recipes/recipe_history.json`
- Generate `recipes/YYYY-MM-DD_grocery_list.md`

Generation takes roughly **2–10 minutes** depending on your hardware and model.

### Generate the printable PDF

Once the week's recipes exist in `recipes/`, double-click **`make_pdf.bat`**:

```bat
make_pdf.bat
```

The PDF (`recipes/YYYY-MM-DD_meal_plan.pdf`) will contain:
- A cover page with the week date
- Each day's recipe on its own page
- The grocery list as the final section
- Page numbers throughout

#### Targeting a specific week

By default `make_pdf.bat` picks the most recently generated week. To target an older week, open `make_pdf.bat` in Notepad, find the `docker run` block, and add:

```bat
-e DATE=2026-05-21 ^
```

## Configuration

All options are set via environment variables. You can edit the defaults directly in `run.bat` or `make_pdf.bat`, or pass them on the command line.

| Variable | Default | Description |
|---|---|---|
| `OLLAMA_MODEL` | `llama3.1` | Any model you have pulled in Ollama (e.g. `mistral`, `llama3.2`) |
| `OLLAMA_HOST` | `host-gateway` | Hostname Docker uses to reach the Windows host — don't change this unless needed |
| `OLLAMA_PORT` | `11434` | Ollama's port |
| `OUTPUT_DIR` | `/output` | Inside the container — maps to `recipes/` on your machine |
| `DATE` | *(latest)* | `YYYY-MM-DD` — target a specific week when generating the PDF |

### Changing the model

Open `run.bat` and change the `-e OLLAMA_MODEL=llama3.1` line, for example:

```bat
-e OLLAMA_MODEL=mistral ^
```

Make sure you've pulled the model first in Ollama:

```
ollama pull mistral
```

### Changing family preferences

Family details, dietary restrictions, and meal style are all defined in `meal_planner.rb` in the `FAMILY_CONTEXT` constant. Edit that block to match your family:

```ruby
FAMILY_CONTEXT = <<~CTX
  Family details:
  - 5 people (2 adults, 3 kids)
  - Peanut allergy (strict - no peanuts or peanut products)
  - No pork of any kind
  - No fish or seafood
  - Onions are not a favorite (minimize or omit)
  - Prefer chicken and beef; open to some lamb
  - Higher protein, lower carb meals preferred
  - Rice preferred over potatoes for starches

  Setting & season:
  - Midwest United States family in summer
  - Grilling outdoors is encouraged and preferred when practical
  - Favour seasonal summer produce: sweet corn, zucchini, tomatoes, cucumbers,
    green beans, bell peppers, and fresh herbs
  - Meals should be lighter and heat-friendly — avoid heavy braises or meals
    that require long oven time on hot days
CTX
```

The `Setting & season` block is entirely optional but makes a real difference — the model will tailor meals to what's in season, how hot it is, and whether grilling is practical. Update it each season or whenever your circumstances change.

After editing, the image needs to be rebuilt. Delete the existing image in Docker Desktop, then run `run.bat` — it will rebuild automatically.

## Recipe history

Every meal generated is recorded in `recipes/recipe_history.json`:

```json
[
  { "date": "2026-05-21", "day": "Monday", "meal_name": "Lemon Herb Roast Chicken" },
  { "date": "2026-05-22", "day": "Tuesday", "meal_name": "Beef Kofta with Rice" }
]
```

This file is cumulative — it grows with every run and is always fed back into the prompt so the model avoids repeating meals. After several weeks you'll have a rich, varied rotation.

To reset the history and allow meals to repeat, delete `recipes/recipe_history.json`.

## Troubleshooting

**`Connection failed` or `Cannot reach Ollama`**
- Make sure Ollama is running (check your system tray)
- Confirm you set `OLLAMA_HOST=0.0.0.0` in CMD and restarted Ollama
- Check Windows Firewall isn't blocking port `11434`

**`Build failed` / Dockerfile errors**
- Make sure all four files (`Dockerfile`, `meal_planner.rb`, `make_pdf.py`, `run.bat`) are in the same folder
- Run the `.bat` files from that folder, not from a shortcut elsewhere

**PDF is missing some days**
- The PDF generator only picks up files matching the date prefix of the grocery list
- If a day failed during generation, re-run `run.bat` — it will regenerate missing days (though it won't overwrite existing ones)

**Ollama generates slow or times out**
- Larger models (`llama3.1:70b`) need significant RAM/VRAM; stick to the default `llama3.1` (8B) for speed
- The scripts use a 5-minute timeout per request — if your machine is very slow, increase `http.read_timeout` in `meal_planner.rb`
